이 문서는 수집, 검수, 콘텐츠 생성, 화면 구현, 배포까지의 작업 순서와 완료 조건을 관리합니다. 완료 조건을 충족하기 전에는 다음 대규모 단계로 확장하지 않습니다.

## 기본 결정

- 두 작품은 하나의 사이트에서 제공하지만 콘텐츠와 용어 데이터는 작품별로 분리한다.
- 배포 저장소는 `ss-park-0930/tearing-saga-series-publish`를 사용한다.
- 사이트 소스는 `ss-park-0930/tearing-saga-series-publish`, 패치 파일 배포는 `ss-park-0930/tearing-saga-release`와 `ss-park-0930/berwick-saga-release`로 분리한다.
- 커스텀 도메인 연결 전 기본 배포 경로는 `/tearing-saga-series-publish/`를 사용한다.
- 1편은 패치 검수가 끝나기 전까지 일본어 게임 원문을 기준 표기로 사용하고 한국어 후보를 검수 상태와 함께 표시한다.
- 2편은 한글패치 프로젝트에서 승인된 캐릭터·장비·아이템 한국어명을 기준 표기로 사용한다.
- 검수된 한국어 장 제목은 계속 사용한다.
- 온라인 공략 원문은 저장하거나 번역 복제하지 않고 사실과 출처만 구조화한 뒤 새로 서술한다.
- 전략 평가는 수치·이벤트 같은 사실 데이터와 분리한다.

## 1단계 — 데이터 모델과 검수 규칙

### 작업

1. 엔티티, 사실, 가이드 문서의 안정적인 ID 규칙을 정한다.
2. 일본어 기준명과 한국어 후보를 분리한다.
3. 모든 사실에 출처와 확인일을 연결한다.
4. 교차 검증, 충돌, 사람 검수 상태를 표현한다.
5. 데이터 검사기를 만든다.

### ID 규칙

- 캐릭터: `trs1-character-fix000433`
- 무기: `trs1-weapon-fix000025`
- 아이템: `trs1-item-fix000152`
- 클래스: `trs1-class-fix000228`
- 스킬: `trs1-skill-fix000750`
- 장: `trs1-chapter-01`, `trs1-chapter-26a`
- 사실: `<subject-id>-<field>-<순번>`

화면 URL은 사람이 읽을 수 있는 slug를 사용하되 내부 관계는 위 ID로 연결합니다. 이름이 한국어로 바뀌어도 ID와 링크 관계는 바뀌지 않습니다.

### 완료 조건

- 승리·패배 조건, 출격 수, 영입, 대화, 증원, 아이템, 놓치기 쉬운 조건을 표현한다.
- 사실 데이터에는 최소 한 개의 직접 출처가 있다.
- 중요한 조건과 수치는 가능한 경우 독립 출처 두 개 이상에서 대조한다.
- 출처가 충돌하면 `conflict`로 남기고 공략문에 단정적으로 쓰지 않는다.
